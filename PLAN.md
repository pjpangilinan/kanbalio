# Portfolio Website — Full Build Plan

> **Full Stack Developer · Glassmorphism / Futuristic · GitHub Pages**

---

## Overview

A single-page React portfolio with four scrollable sections, a unique kanban board for projects, and a GitHub-automated LaTeX résumé. Hosted on GitHub Pages via `gh-pages` or GitHub Actions.

### 03 — Projects (Kanban Board)

This is the signature section. Instead of a static project grid, viewers see your real work-in-progress as a kanban board.

#### Column Behavior

- **One column visible at a time** on both mobile and desktop
- Left `‹` and right `›` arrow buttons cycle between columns
- Column label and count (e.g. `In Progress · 1`) displayed above the cards
- Smooth horizontal slide animation between columns using `AnimatePresence`

#### Column Definitions

| Column | Label | Card accent |
|---|---|---|
| 0 | To Do | Violet border |
| 1 | In Progress | Pulsing cyan border |
| 2 | Done | Green border |

Cards in the **In Progress** column get a CSS keyframe animation:

```css
@keyframes pulse-border {
  0%, 100% { border-color: rgba(0, 212, 255, 0.3); }
  50%       { border-color: rgba(0, 212, 255, 0.9); }
}
.card-active { animation: pulse-border 2s ease-in-out infinite; }
```

#### KanbanBoard Component Logic

```jsx
const COLUMNS = ['To Do', 'In Progress', 'Done']
const [active, setActive] = useState(0)

const prev = () => setActive(i => (i - 1 + 3) % 3)
const next = () => setActive(i => (i + 1) % 3)

// AnimatePresence with direction-aware x offset
<AnimatePresence mode="wait" custom={direction}>
  <motion.div
    key={active}
    custom={direction}
    variants={slideVariants}
    initial="enter"
    animate="center"
    exit="exit"
    transition={{ duration: 0.35, ease: 'easeInOut' }}
  >
    {/* render cards for COLUMNS[active] */}
  </motion.div>
</AnimatePresence>
```

```jsx
const slideVariants = {
  enter:  dir => ({ x: dir > 0 ?  300 : -300, opacity: 0 }),
  center:      () => ({ x: 0, opacity: 1 }),
  exit:   dir => ({ x: dir > 0 ? -300 :  300, opacity: 0 }),
}
```

## GitHub Workflows

### 1. Deploy to GitHub Pages — `.github/workflows/deploy.yml`

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [main]
    paths-ignore:
      - 'resume/**'   # resume changes handled by separate workflow

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
```

### 2. Auto-build LaTeX Résumé — `.github/workflows/build-resume.yml`

Triggers whenever you push a change to `resume/resume.tex`. Compiles it to PDF and commits `public/resume.pdf` back to the repo, then the deploy workflow picks it up automatically.

```yaml
name: Build LaTeX Résumé

on:
  push:
    branches: [main]
    paths:
      - 'resume/**.tex'

jobs:
  build-resume:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Compile LaTeX to PDF
        uses: xu-cheng/latex-action@v3
        with:
          root_file: resume/resume.tex
          latexmk_use_xelatex: true   # use XeLaTeX for better font support

      - name: Move PDF to public/
        run: mv resume.pdf public/resume.pdf

      - name: Commit updated PDF
        uses: stefanzweifel/git-auto-commit-action@v5
        with:
          commit_message: "ci: update resume.pdf from resume.tex"
          file_pattern: public/resume.pdf
```

> **How the résumé flow works:**
> 1. You edit `resume/resume.tex` and push to `main`
> 2. `build-resume.yml` fires, compiles the `.tex` to PDF using `xu-cheng/latex-action`
> 3. The PDF is committed back to `public/resume.pdf`
> 4. `deploy.yml` fires on that commit, rebuilds the Vite site and publishes it
> 5. The `View Résumé` button in the Contact section always serves the latest version

## Framer Motion Animation Map

| Element | Animation | API |
|---|---|---|
| Hero text | Stagger fade-up on load | `variants` + `staggerChildren` |
| Role text cycling | Opacity crossfade | `AnimatePresence` + `key` |
| Avatar glow ring | Continuous scale pulse | `animate` + `repeat: Infinity` |
| Experience timeline line | Scroll-linked draw | `useScroll` + `scaleY` |
| Experience cards | Slide in from sides | `whileInView` + `x` offset |
| Kanban column switch | Direction-aware slide | `AnimatePresence` + custom direction |
| Kanban cards | Hover lift | `whileHover` `y: -4` |
| Contact form button | State-based text swap | `AnimatePresence` on label |
| Particle background | Floating drift loop | `animate` + `repeat: Infinity` |

## Notes

- **No backend required** — EmailJS handles form submissions, GitHub Actions handles PDF compilation, GitHub Pages serves everything statically.
- **Resume update flow is zero-friction** — edit the `.tex` file, push, done. The PDF on the live site updates automatically within ~2 minutes.
- All 3 kanban columns are visible on desktop as well but only one at a time (arrow navigation) — this keeps the futuristic focused feel instead of a crowded grid.
